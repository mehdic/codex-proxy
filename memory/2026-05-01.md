- Claude proxy had a 3-layer keepalive design, but the likely false-timeout mechanism was that OpenClaw did not receive/count valid non-empty assistant content during the 300s window.
- Important code detail found in `src/server/routes.ts`:
  - The intended zero-width-space heartbeat constant appeared as `const ZWSP = "";` in observed output, i.e. effectively empty instead of literal `"\u200B"`.
  - When `bridgeTools = true`, keepalive deltas can become role-only or empty (`{ role: "assistant" }` or `{}`), which may keep HTTP/SSE alive but not reset OpenClaw’s model-output idle detector.
- Core diagnosis: the proxy may have been “breathing” at the HTTP/SSE layer but not “speaking” in OpenClaw-countable OpenAI-compatible assistant content.
- Recommended Claude proxy fix:
  - Use an explicit literal heartbeat: `const HEARTBEAT = "\u200B";`
  - Emit non-empty content even with tools/bridge enabled:
    - first heartbeat: `{ role: "assistant", content: HEARTBEAT }`
    - later heartbeats: `{ content: HEARTBEAT }`
  - Avoid empty `delta: {}` and role-only heartbeat chunks for long-running turns.
- Recommended observability updates:
  - request-scoped logging for request id, model, runtime, stream flag, `bridgeTools`, first byte time, first countable content time, keepalive count, client disconnect time, final completion time.
  - Treat `res.on("close")` as client-abandon: kill/discard Claude subprocess immediately rather than allowing stale work to continue.
- Recommended tests:
  - stream-json + tools emits non-empty heartbeat chunks before 300s.
  - OpenClaw-style parser counts heartbeat as assistant activity.
  - no empty `delta: {}` keepalives.
  - heartbeat uses literal `"\u200B"`, not an accidentally empty/invisible pasted char.
